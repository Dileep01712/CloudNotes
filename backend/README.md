# CloudNotes Backend

Express.js REST API for CloudNotes — secure authentication, MongoDB storage, email-based OTP flows, and production-hardened middleware.

## Tech stack
- Node.js + Express
- MongoDB with Mongoose
- Authentication: JWT access tokens (short-lived) + refresh tokens (30 days, HTTP-only cookie)
- Email: Nodemailer (Gmail SMTP configured via env)
- Security middleware: Helmet, express-rate-limit, express-mongo-sanitize, xss-clean
- Other: morgan logging, compression, cookie-parser, express-validator

## Quickstart

1. Copy or create a `.env` file at the project root (backend). Required environment variables are listed below.
2. Install dependencies:
	 - `cd backend`
	 - `npm install`
3. Start in development:
	 - `npm run dev` (requires `nodemon`)
4. Start in production:
	 - `npm start`

## Required environment variables

- `MONGO_URI` — MongoDB connection string (required). If missing, the server exits. See [backend/db.js](backend/db.js).
- `PORT` — optional; defaults to `5000`.
- `NODE_ENV` — `production` or `development`. Affects cookie `secure` and `sameSite` settings.
- `CORS_ORIGIN` — allowed origin for CORS (default `http://localhost:5173`).
- `JWT_SECRET` — secret for access tokens (default fallback used if not set, but always set in production).
- `JWT_REFRESH_SECRET` — secret for refresh tokens (default fallback used if not set).
- `EMAIL_USER` — Gmail address used for Nodemailer `from` address.
- `EMAIL_PASS` — Gmail app password or account password (use app password / secure method).
- `EXPIRATION_MS_DEFAULT` — default expiration duration in milliseconds used for notes/folders if `*_EXPIRATION_MS` are not provided.
- `NOTE_EXPIRATION_MS` (optional) — override for note expiration milliseconds.
- `FOLDER_EXPIRATION_MS` (optional) — override for folder expiration milliseconds.

Notes:
- `Otp` documents expire after 5 minutes (TTL index set to 300 seconds).
- The server logs an error if `NOTE_EXPIRATION_MS` or `FOLDER_EXPIRATION_MS` are invalid; supply `EXPIRATION_MS_DEFAULT` or valid overrides.

## Database connection behavior

- The MongoDB connection is in [backend/db.js](backend/db.js).
- `mongoose.connect()` uses `serverSelectionTimeoutMS: 5000`.
- If the initial connection fails, the code will retry up to 5 times with a 5-second delay between attempts, then exit if still failing.
- On `disconnected` events, the connection attempts automatic reconnection.
- On `SIGINT`, the connection is closed gracefully.

## Server behavior & middleware

Configured in [backend/index.js](backend/index.js):

- `app.set("trust-proxy", 1)` — for running behind proxies/load balancers.
- `helmet()` — standard security headers.
- `compression()` — response compression.
- `morgan('combined')` — request logging.
- `express.json({ limit: '10kb' })` — JSON body parsing with a 10KB limit.
- `express-mongo-sanitize()` — sanitizes user-supplied data to prevent NoSQL injection.
- `xss-clean()` — basic XSS protection on request data.
- `cookie-parser()` — parse cookies (refresh tokens stored as cookies).
- `cors` configured via `CORS_ORIGIN` and `credentials: true`.
- Global rate limiter applied to `/api/`:
	- `windowMs: 60 * 1000` (1 minute), `max: 100` requests.
	- Skips `/health`.
- `authLimiter` applied to `/api/auth`:
	- `windowMs: 15 * 60 * 1000` (15 minutes), `max: 10`, `skipSuccessfulRequests: true`.
	- Prevents brute-force on auth endpoints.

## Authentication & token strategy

- Access tokens:
	- JWT signed with `JWT_SECRET`.
	- Short-lived (15 minutes) — generated by `UserSchema.methods.generateAccessToken()` in [backend/models/User.js](backend/models/User.js).
	- Sent/used as `auth-token` header for protected routes; verified by `fetchuser` middleware.
- Refresh tokens:
	- JWT signed with `JWT_REFRESH_SECRET`.
	- Long-lived (30 days).
	- Stored in the user's document (`refreshToken`) and sent to the browser via an HTTP-only cookie named `refreshToken`.
	- Cookie options:
		- `httpOnly: true`
		- `secure: true` in production
		- `sameSite: 'None'` in production, otherwise `'Strict'`
		- `maxAge: 30 days`
- Single-session enforcement:
	- On sign-in and refresh, the server updates the `User.refreshToken` field. If a previously-issued refresh token is reused after rotation, the check fails and the cookie is cleared (prevents reuse across devices).
- Refresh flow:
	- POST `/api/auth/refresh-token` — verifies cookie `refreshToken`, ensures it matches the user's stored token, issues a new access token and refresh token (rotating refresh tokens), and updates the cookie.

## OTP flows & email

- OTP documents stored in [backend/models/Otp.js](backend/models/Otp.js):
	- Fields: `email`, `otp` (6-digit string), `attempts` (counts wrong attempts), `createdAt`.
	- TTL: expires after 300 seconds (5 minutes).
- Email sending:
	- Nodemailer configured with Gmail via `EMAIL_USER` and `EMAIL_PASS` in [backend/routes/auth.js](backend/routes/auth.js).
	- HTML email templates included for:
		- Verification code (`/api/auth/send-otp`)
		- Account recovery code (`/api/auth/forgot-password`)
	- OTP generation: 6-digit random numeric code.
	- After 3 incorrect OTP attempts, OTP record is deleted and user must request a new code.
- Routes:
	- `POST /api/auth/send-otp` — request verification OTP for account creation (validates `name`, `email`, `password`).
	- `POST /api/auth/forgot-password` — request OTP for password reset.
	- `POST /api/auth/reset-password` — provide `email`, `otp`, and `password` to reset password.

## API endpoints (summary)

Auth routes (see [backend/routes/auth.js](backend/routes/auth.js)):

- POST `/api/auth/send-otp`  
	- Body: `{ name, email, password }`  
	- Validates inputs, creates an OTP, emails the code (5 min TTL).  
- POST `/api/auth/create-user`  
	- Body: `{ name, email, password, otp }`  
	- Validates OTP, creates user, issues `accessToken` (response) and sets HTTP-only `refreshToken` cookie.  
- POST `/api/auth/signin`  
	- Body: `{ email, password }`  
	- Validates credentials, issues `accessToken` and `refreshToken` cookie; stores refresh token on user.  
- POST `/api/auth/signout`  
	- Clears cookie and nulls `User.refreshToken` if possible.  
- POST `/api/auth/refresh-token`  
	- Refresh cookie-based refresh token, rotate refresh token and return new access token.  
- PUT `/api/auth/update-user` (protected)  
	- Body: `{ name?, email? }` — updates profile (validates unique email).  
- POST `/api/auth/get-user` (protected)  
	- Returns current user (excludes password).  

Note routes (see [backend/routes/note.js](backend/routes/note.js)) — all protected by `fetchuser`:

- GET `/api/note/fetch-all-notes` — returns all user's notes, sorted by creation descending.
- GET `/api/note/fetch/:directoryId` — `directoryId` can be a folder `_id` or the string `none` (for root notes).
- POST `/api/note/add-note` — Body: `{ title?, description, tag?, parent? }` — validates parent ID, formats text (capitalizes sentences, normalizes tags).
- PUT `/api/note/update-note/:id` — Partial updates (title, description, tag, parentId, pinnedAt, expireAt). Updates `updatedAt` if content changed.
- DELETE `/api/note/delete-note/:id` — Hard-deletes a note.

Folder routes (see [backend/routes/folder.js](backend/routes/folder.js)) — all protected:

- GET `/api/folder/fetch-all-folders` — returns all user's folders.
- POST `/api/folder/create-folder` — Body: `{ title, parent? }` — validates parent, prevents duplicate names in same parent.
- PUT `/api/folder/update-folder/:id` — Updates title, parent (prevents self-parenting), color, pinnedAt, expireAt; updates child notes on expire toggles.
- DELETE `/api/folder/delete-folder/:id` — Recursively deletes folder and child folders and all notes inside (`deleteFolderAndChildren` helper).

## Validation:
- Uses `express-validator` throughout for input validation (emails, password length, Mongo IDs).
- Error responses are consistent JSON `{ success: false, ... }` for validation errors or messages.

## Models & database notes

User (`backend/models/User.js`)
- Fields: `name`, `email` (unique, strict validator), `password` (hashed via `bcryptjs`, select: false), `refreshToken`, `createdAt`, `updatedAt`.
- Hooks:
	- `pre('save')` hashes password and updates `updatedAt`.
	- `pre` update hooks set `updatedAt`.
- Methods:
	- `comparePassword(candidatePassword)` — bcrypt compare.
	- `generateAccessToken()` — signs with `JWT_SECRET` (expires 15m).
	- `generateRefreshToken()` — signs with `JWT_REFRESH_SECRET` (expires 30d).
- Index on `email`.

Otp (`backend/models/Otp.js`)
- TTL index: documents expire after 300s (5 minutes).
- Tracks `attempts` to limit wrong OTP tries.

Notes (`backend/models/Note.js`)
- Fields: `user` (ObjectId, indexed), `title`, `description`, `tag`, `parent` (folder ref, indexed), `pinnedAt`, `trashedAt`, `expireAt`.
- `typeName` set to `'note'` and immutable.
- Indexes:
	- `{ user: 1, parent: 1 }` for fast queries per user/directory.
	- TTL index on `expireAt` with `expireAfterSeconds: 0` to let Mongo delete expired documents automatically.
- JSON transform normalizes dates and removes `__v`.

Folder (`backend/models/Folder.js`)
- Similar structure to notes: `user`, `title`, `parent`, `color`, `pinnedAt`, `trashedAt`, `expireAt`.
- `typeName` `'folder'`, immutable.
- Indexes and TTL on `expireAt` like notes.
- `findPath` helper in route builds URL-friendly path segments from folder titles.

## Error Handling & logging

- Central error handler in [backend/index.js](backend/index.js) maps common errors:
	- Duplicate key (`code === 11000`) → 400 with message.
	- Mongoose `ValidationError` → 400 with details array.
	- JWT errors (`JsonWebTokenError`, `TokenExpiredError`) → 401.
	- Other errors → 500 with stack logged.
- Requests logged with `morgan('combined')`.

## Graceful shutdown & reliability

- `index.js` listens for `SIGTERM` / `SIGINT` / `unhandledRejection` / `uncaughtException` and triggers `gracefulShutdown`.
- On shutdown the server closes and the MongoDB connection is closed.
- `db.js` auto-reconnects if disconnected and retries initial connect up to 5 attempts.

## Security & production recommendations

- Set strong `JWT_SECRET` and `JWT_REFRESH_SECRET` in production; do not rely on defaults.
- Use HTTPS (TLS) and set `NODE_ENV=production` so refresh cookie `secure` and `sameSite` settings are correct.
- Use a Gmail app password or a third-party transactional email provider rather than storing a plain account password.
- Limit public CORS origins via `CORS_ORIGIN` (do not leave open to `*` in production).
- Consider additional logging/monitoring for token refresh failures and failed OTP attempts.
- Rotate and secure `EMAIL_PASS` and other secrets via a secrets manager or environment configuration.

## Notes & gotchas (observations from code)
- OTP TTL is 5 minutes (`expires: 300`) — any flows relying on OTP should complete within that window.
- The code logs an error and falls back if `NOTE_EXPIRATION_MS` or `FOLDER_EXPIRATION_MS` are invalid — ensure `EXPIRATION_MS_DEFAULT` or the specific env vars are defined and numeric.
- `fetchuser` expects access token in `auth-token` header. If missing or invalid, returns 401.
- The refresh-token route rotates refresh tokens and checks stored `User.refreshToken` to implement single-session semantics.
